项目计划的四项工作

在项目的整个生命周期里，人们会一遍遍向项目计划提出四个问题。什么时候完成？谁做什么？要花多少钱？我们在计划内吗？

一个能答好其中一个、另外三个靠手工去答的计划，不是计划，是计划的照片。电子表格里画出的甘特图和真正的进度计划工具，差别就在这里，而后者到底必须做到什么，值得讲具体。

01 — 规划时间

这件事究竟什么时候能完成？

完成日期不是你选出来的。它是从你录入的依赖关系和工期里落下来的，而算出它的算术方法就是关键路径法。改动一个工期，所有下游日期都会移动——立刻移动，而不是等谁把条形图重画一遍。

这在底层需要什么：四种依赖类型、八种约束类型、拆分任务与周期性任务、九种工时分布曲线、自定义日历、工作周、实耗工期。这些机械部件并不光鲜，但正是它们把一份能经受现实冲击的进度计划，和一份在第三周就被放弃的进度计划区分开来。

02 — 规划资源

谁被压满了？谁在闲着？

每一项任务都会消耗某个人。不为此建模的计划会毫不犹豫地告诉你：三个人可以在同一周里各做两项全职任务。

给任务分配工时、材料、成本、预算和通用资源。资源使用状况和团队规划器视图会在过度分配出现的那一刻就把它显出来，而不是等到工期崩掉的那一周。自动平衡按优先级、可用时差或 ID 解决冲突——如果你这样要求，就只在可用时差范围内解决。A–E 费率表承载带生效日期的费率和随时间变化的可用量，因为人一年里成本并不相同，也并非全年可用。

03 — 规划成本

究竟要花多少钱？

零件可以定价。给整个计划定价要难得多，因为人工、加班、材料和供应商账单，全都挂在一份不停移动的进度计划上。

所以成本必须从资源费率、固定成本和材料消耗向上汇总，固定成本按开始、结束或按比例分摊计提，并且要与进度计划同一拍子地重算。十三个挣值列（BCWS、BCWP、CPI、SPI、EAC、VAC、TCPI 等）把这些变成管理层真正会看的两个数字：我们是提前还是落后，是超支还是结余。

04 — 跟踪进展

我们在计划内吗？

“在计划内”只有相对于某个东西才有意义。那个东西就是基准——当初承诺时的计划，与现在的计划并排保存。

十一条基准（0–10）加十份临时计划意味着你可以保留历史，而不是每次重新批准就覆盖一次。五十五个基准列和五个偏差列给出比较；基准条形叠加在甘特图上，让你不用读表格就能看见。更新项目和重新安排未完成工作会把状态日期之前没有发生的一切一次性移动，而不是两百次操作。

把四者串起来的那一部分

这四项工作并不是四个工具。它们之所以待在同一个文件里，是因为每一个答案都会改变另外三个：一项任务滑期会移动完成日期，完成日期会移动十一月谁忙，那会移动成本，而成本会移动你上报的偏差。

Ingantt 在浏览器里把这四项都做了，深度与 Microsoft Project 相当——再加上用于起草和修改计划的 AI、用于共享的 Google Drive，以及 MS Project 与 Primavera 文件的进出。没有单独的 AI 订阅，也不需要新建账号。

如果你是带着文件从 MS Project 或 Primavera 过来的，先打开一个，看看这四个答案是否原样返回。
