在“% 完成”里填上 50，到底对你的进度计划做了什么

它看上去是整行里最无害的一个字段。你输入 50，进度条填到一半，例会上大家点头通过。但在一个保存实际值的进度计划工具里，它一点也不无害：这一个数字会替你写进另外好几个字段，而如果你不知道是哪些，你的偏差报告就会讲出一个你并不想讲的故事。

下面是 Ingantt for Web 和 Android 里的真实行为。

超过 0% 会写入实际开始时间

任务的完成率一旦超过 0%，就意味着它已经开始，于是 Ingantt 写入一个实际开始时间（Actual Start）。不是计划开始时间，而是实际的。如果这个任务其实晚了三天才开工，而你只录入进度、没有更正实际开始时间，进度计划就会认为它按时开始、只是走得慢。这是两个不同的问题、两种不同的处理，而其中只有一个是你的。

100% 会写入实际完成时间

把任务推到 100%，Ingantt 会写入一个实际完成时间（Actual Finish）。这是基准比较所读取的字段，所以值得写对，而不是写快。

工期会在底下重新计算

实际工期（Actual Duration）和剩余工期（Remaining Duration）会根据百分比重新计算。十天的任务完成一半，就是五天做完、五天待做——直到你说不是这样。如果工作确实完成了 50%，但剩下的一半要花九天而不是五天，诚实的修改应落在剩余工期上，而不是“% 完成”上。百分比是事实的输出结果，不是事实的替代品。

只有你要求了，工时才会跟着动

实际工时（Actual Work）和剩余工时（Remaining Work）只有在项目选项 “Updating task status updates resource status” 打开时，才会随“% 完成”更新。这就是最常让人意外的设置：进度看起来在跟踪，工时和成本却纹丝不动，谁也看不出原因。如果你的挣值数字看起来冻住了，先检查这个开关。

落到实处的版本

  • 按你真正想要的状态日期录入进度，而不是默认的今天。
  • 任务开工晚了就更正实际开始时间。百分比承载不了这条信息。
  • 把拖延推进剩余工期，而不是压低百分比。
  • 任务状态该不该驱动资源状态，决定一次，之后别再动它。

Ingantt 帮助中心有更详细的说明：录入进度、实际值与剩余值列，以及基准——上面这一切最终都汇入这项比较。
