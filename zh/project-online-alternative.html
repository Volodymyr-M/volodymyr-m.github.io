哪些内容能带出 Project Online，哪些不能

导出并不是一件整体的事。排程随项目文件一起走，但 PMO 围绕这份排程搭建的大部分内容不会，必须在服务关闭前另行取出。

一个 .MPP 或 MS Project XML 文件能够完整描述一份排程，而且可移植，这正是它值得留存的原因。打开之后，计划确实是完好的，连依赖关系的延隔时间和任务日历都在。

它从来不负责承载的，是 Project Online 在排程之外加上的那一层。工时表历史、企业资源池、查阅表、项目组合汇总，以及存放在每个项目 SharePoint 网站中的问题、风险和文档，全都保存在项目文件之外，只能通过 OData API 或数据导出脚本以 CSV、JSON 的形式取出。

实际结果是：一个装满 .MPP 文件的文件夹，是你计划的完整备份，却是你 PMO 的不完整备份。两者都值得保留，而能在排程工具中打开的只有其中一个。

微软推荐的去向 以及各自的花费

离开 Project Online 有三条官方路径，价格和覆盖范围差别很大。哪条合适，取决于你要替换的是一套排程做法，还是整个 PMO 平台。

Planner Premium 是多数 Project Online 客户被引导前往的方向。它通过 Planner Power App 向导导入 .MPP，在 Planner and Project Plan 3 下支持依赖关系、关键路径和基准。决定之前有两点值得知道：导入是有损的，自定义字段上限为十个，不受支持的 Project 功能会被丢弃或调整；而排程功能要到每用户每月 30 美元的 Plan 3 才提供，每月 10 美元的 Plan 1 并不包含。资源平衡与挣值在任何层级都不提供。

Project Server Subscription Edition 最接近同等替换，因为它本质上就是同一个产品跑在你自己的基础设施上。企业自定义字段、工时表、项目组合管理和 PWA 模型大体都能保留。代价是服务器许可证加上 CAL 再加上运行环境，还有一个以月而非以天计的实施项目，所以它更适合已经拥有 SharePoint Server 和相应运维人员的组织。

Dynamics 365 Project Operations 适合以项目为核心的企业，也就是排程与报价、合同、开票和收入确认绑定在一起的场景。它同时也是三者中投入最大的：完整用户许可证为每用户每月 135 美元，而且这是 ERP 规模的实施，不是一次迁移。

Ingantt 有意不属于其中任何一个。它以每用户每月 5.99 美元替代排程这一半工作，也就是计划本身、计算引擎和跟踪字段，并且无需任何实施就能打开你已有的文件。如果你真正需要的是项目组合与治理那一层，诚实的答案就是上面三者之一，这个页面宁可这样告诉你，也不想绕开它去推销。

这取决于 Project Online 的哪一半对你重要。如果你需要的是企业级项目组合管理，比如立项工作流、阶段评审、企业资源池、工时表和 OData 报表，那么诚实的答案是 Project Server Subscription Edition 或专门的 PPM 产品，而搭建它本身就是一个正经项目。如果你日常真正用到的是排程，也就是任务、依赖关系、关键路径、基准、资源和成本跟踪，那么一个能读取你导出文件的排程工具可以让你立刻恢复工作，不需要迁移方案。Ingantt 属于后者。
