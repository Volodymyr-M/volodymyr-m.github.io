เปิดสิ่งที่คุณส่งออกไว้

โครงการที่บันทึกผ่าน Project บนเดสก์ท็อปจะอยู่ในรูปแบบ .MPP ส่วนสคริปต์ส่งออกจำนวนมากจะให้ไฟล์ข้อมูลแทน Ingantt อ่าน .MPP, MS Project XML และ CSV ได้โดยตรงในเบราว์เซอร์ ไม่ต้องมีสิทธิ์ใช้งาน Microsoft Project ไม่ต้องใช้บริการแปลงไฟล์ และไม่ต้องมีเครื่องเสมือน Windows

การจัดตารางตามเส้นทางวิกฤตอย่างแท้จริง

ความสัมพันธ์ระหว่างงาน ข้อจำกัด ปฏิทิน และเส้นทางวิกฤตที่คำนวณใหม่ทันทีเมื่อวันที่ขยับ แผนที่ใช้เวลาหลายปีสร้างขึ้นยังคงเป็นแผน ไม่ใช่รายการการ์ดแบนๆ

เส้นฐานและมูลค่าที่ได้รับ

เส้นฐาน วันที่จริงเทียบกับวันที่วางแผน เปอร์เซ็นต์ความคืบหน้า การติดตามต้นทุน และมูลค่าที่ได้รับ ซึ่งเป็นฟิลด์ติดตามที่ตารางงานของ PMO พกมาด้วย ไม่ใช่แค่ชื่องาน

ไม่ต้องมีเทนแนนต์ ไม่ต้องมีโครงการย้ายระบบ

ลงชื่อเข้าใช้ด้วยบัญชี Google แล้วเปิดไฟล์ได้เลย ไม่มีสภาพแวดล้อมที่ต้องจัดเตรียม ไม่มีเซิร์ฟเวอร์ที่ต้องติดตั้ง และไม่มีช่วงเปลี่ยนผ่านยาวเป็นไตรมาสก่อนที่ใครสักคนจะกลับมาอ่านตารางงานได้

แค่ต้องการอ่านไฟล์เดียวใช่ไหม

ถ้าเรื่องมีแค่เปิด .MPP แล้วอ่านตารางงาน ในเบราว์เซอร์ใช้เวลาราวสามสิบวินาที — ดูวิธีเปิดไฟล์ .MPP

อะไรที่ออกมาจาก Project Online ได้ และอะไรที่ไม่ได้

การส่งออกไม่ใช่ก้อนเดียว ตารางงานเดินทางมาพร้อมไฟล์โครงการ แต่สิ่งที่ PMO สร้างขึ้นรอบตารางงานนั้นส่วนใหญ่ไม่ได้มาด้วย และต้องดึงออกมาต่างหากก่อนบริการจะปิด

ไฟล์ .MPP หรือ MS Project XML อธิบายตารางงานได้ครบถ้วนและเคลื่อนย้ายได้ นี่คือเหตุผลที่มันเป็นรูปแบบที่ควรเก็บไว้ เปิดขึ้นมาแล้วแผนยังสมบูรณ์จริง ลงลึกถึงระยะเวลาเหลื่อมของความสัมพันธ์ระหว่างงานและปฏิทินของแต่ละงาน

สิ่งที่ไฟล์เหล่านี้ไม่เคยถูกออกแบบให้พกพาคือชั้นที่ Project Online สร้างครอบตารางงานไว้ ประวัติใบบันทึกเวลา แหล่งทรัพยากรระดับองค์กร ตารางค้นหา ยอดรวมระดับพอร์ตโฟลิโอ รวมถึงประเด็นปัญหา ความเสี่ยง และเอกสารที่อยู่ในไซต์ SharePoint ของแต่ละโครงการ ทั้งหมดถูกเก็บไว้นอกไฟล์โครงการ และดึงออกมาได้ทางเดียวคือผ่าน OData API หรือสคริปต์ส่งออกข้อมูล ในรูปแบบ CSV หรือ JSON

ผลในทางปฏิบัติคือ โฟลเดอร์ที่เต็มไปด้วยไฟล์ .MPP คือข้อมูลสำรองที่ครบถ้วนของแผนงานคุณ แต่เป็นข้อมูลสำรองที่ไม่ครบของ PMO คุณ ทั้งสองอย่างควรเก็บไว้ และมีเพียงอย่างเดียวที่เปิดได้ในเครื่องมือจัดตารางงาน

เดินทางมาในไฟล์ .MPP หรือ XML

  • งาน งานย่อย และโครงสร้างลำดับชั้น
  • ความสัมพันธ์ระหว่างงานและระยะเวลาเหลื่อม FS, SS, FF, SF
  • ระยะเวลา ปริมาณงาน และวันเริ่มต้นกับวันสิ้นสุด
  • ข้อจำกัดและกำหนดส่ง
  • ปฏิทินโครงการและปฏิทินงาน
  • การกำหนดทรัพยากรและอัตราค่าใช้จ่าย ในรูปทรัพยากรภายในไฟล์
  • เส้นฐานและเส้นทางวิกฤต
  • เปอร์เซ็นต์ความคืบหน้า ค่าจริง และต้นทุน
  • หมุดหมายสำคัญ

ได้เฉพาะผ่าน OData หรือการส่งออกข้อมูล

  • ใบบันทึกเวลาและประวัติงานที่ทำจริง
  • แหล่งทรัพยากรระดับองค์กร
  • ฟิลด์กำหนดเองระดับองค์กรและตารางค้นหา บางส่วน ในรูปฟิลด์ภายในไฟล์
  • รายงานระดับพอร์ตโฟลิโอและข้ามโครงการ
  • ประเด็นปัญหา ความเสี่ยง และสิ่งส่งมอบ รายการใน SharePoint
  • ไซต์โครงการและเอกสาร
  • ประวัติเวิร์กโฟลว์และด่านอนุมัติตามระยะ
  • แบบจำลองความปลอดภัยและสิทธิ์การเข้าถึง

ปลายทางที่ไมโครซอฟท์แนะนำ และค่าใช้จ่ายของแต่ละทาง

มีเส้นทางอย่างเป็นทางการสามทางในการย้ายออกจาก Project Online และทั้งสามต่างกันมากทั้งราคาและขอบเขต ทางไหนเหมาะขึ้นอยู่กับว่าคุณกำลังแทนที่แนวปฏิบัติด้านการจัดตารางงาน หรือแทนที่แพลตฟอร์ม PMO ทั้งระบบ

Planner Premium คือเส้นทางที่ลูกค้า Project Online ส่วนใหญ่ถูกแนะนำให้ไป มันนำเข้า .MPP ผ่านตัวช่วยสร้างใน Planner Power App และในระดับ Planner and Project Plan 3 รองรับความสัมพันธ์ระหว่างงาน เส้นทางวิกฤต และเส้นฐาน มีสองเรื่องที่ควรรู้ก่อนตัดสินใจ การนำเข้ามีการสูญเสียข้อมูล โดยฟิลด์กำหนดเองจำกัดที่สิบฟิลด์ และคุณสมบัติของ Project ที่ไม่รองรับจะถูกตัดออกหรือปรับแก้ ส่วนคุณสมบัติด้านการจัดตารางเริ่มต้นที่ Plan 3 ราคา 30 ดอลลาร์ต่อผู้ใช้ต่อเดือน ขณะที่ Plan 1 ราคา 10 ดอลลาร์ไม่รวมให้ การปรับสมดุลทรัพยากรและมูลค่าที่ได้รับไม่มีให้ใช้ในทุกระดับ

Project Server Subscription Edition ใกล้เคียงกับการแทนที่แบบเทียบเท่ามากที่สุด เพราะโดยพื้นฐานแล้วคือผลิตภัณฑ์เดียวกันที่รันบนโครงสร้างพื้นฐานของคุณเอง มันรักษาฟิลด์กำหนดเองระดับองค์กร ใบบันทึกเวลา การจัดการพอร์ตโฟลิโอ และโมเดล PWA ไว้ได้เกือบครบ ต้นทุนคือสิทธิ์ใช้งานเซิร์ฟเวอร์บวก CAL บวกที่สำหรับรันระบบ พร้อมโครงการติดตั้งที่วัดเป็นเดือนไม่ใช่เป็นวัน ด้วยเหตุนี้จึงเหมาะกับองค์กรที่มี SharePoint Server และทีมงานดูแลอยู่แล้ว

Dynamics 365 Project Operations คือคำตอบที่ถูกต้องสำหรับธุรกิจที่ทำงานเป็นโครงการ ซึ่งตารางงานผูกอยู่กับการเสนอราคา สัญญา การวางบิล และการรับรู้รายได้ ขณะเดียวกันก็เป็นการลงทุนที่ใหญ่ที่สุดในสามทางเลือก ที่ 135 ดอลลาร์ต่อผู้ใช้ต่อเดือนสำหรับสิทธิ์ใช้งานเต็มรูปแบบ และเป็นการวางระบบระดับ ERP ไม่ใช่การย้ายข้อมูล

Ingantt ตั้งใจไม่เป็นทางใดทางหนึ่งในสามนั้น มันแทนที่งานฝั่งจัดตาราง คือตัวแผน กลไกคำนวณ และฟิลด์ติดตาม ในราคา 5.99 ดอลลาร์ต่อผู้ใช้ต่อเดือน และเปิดไฟล์ที่คุณมีอยู่แล้วโดยไม่ต้องวางระบบใดๆ ถ้าสิ่งที่คุณต้องการจริงๆ คือชั้นพอร์ตโฟลิโอและการกำกับดูแล คำตอบที่ตรงไปตรงมาคือหนึ่งในสามทางข้างต้น และหน้านี้ขอบอกคุณตามนั้นดีกว่าจะขายของข้างเคียง

ย้ายออกจาก Project Online — คำถามที่คนถามกันจริงๆ

วันยุติบริการที่ไมโครซอฟท์กำหนดคือ 30 กันยายน 2026 หลังจากนั้นไซต์ Project Online และข้อมูลโครงการที่อยู่ข้างในจะเข้าถึงไม่ได้อีก อินเทอร์เฟซ PWA จะหยุดทำงาน และปลายทางรายงาน OData จะไม่ตอบสนอง ไมโครซอฟท์ไม่ได้ให้คำมั่นเรื่องช่วงอ่านอย่างเดียวหรือโหมดเก็บถาวรหลังยุติบริการ ดังนั้นสิ่งที่ไม่ได้ส่งออกไว้ก่อนควรถือว่าหายไป ไม่ใช่แค่ออฟไลน์ ในทางปฏิบัติ ไฟล์ที่คุณส่งออกไว้คือสำเนาหลักของตารางงานเหล่านั้น และมันต้องเปิดได้ที่ไหนสักแห่ง

ขึ้นอยู่กับว่า Project Online ครึ่งไหนสำคัญกับคุณ ถ้าสิ่งที่คุณต้องการคือการจัดการพอร์ตโฟลิโอระดับองค์กร ทั้งเวิร์กโฟลว์เสนอโครงการ ด่านอนุมัติตามระยะ แหล่งทรัพยากรระดับองค์กร ใบบันทึกเวลา และรายงาน OData คำตอบที่ตรงไปตรงมาคือ Project Server Subscription Edition หรือผลิตภัณฑ์ PPM เฉพาะทาง และการวางระบบก็เป็นโครงการจริงจัง แต่ถ้าสิ่งที่คุณใช้จริงในแต่ละวันคือตารางงาน ทั้งงาน ความสัมพันธ์ระหว่างงาน เส้นทางวิกฤต เส้นฐาน ทรัพยากร และการติดตามต้นทุน เครื่องมือจัดตารางงานที่อ่านไฟล์ส่งออกของคุณได้จะพาคุณกลับมาทำงานต่อได้ทันทีโดยไม่ต้องมีโครงการย้ายระบบ Ingantt เป็นแบบหลัง

เปิดด้วย Ingantt ในเบราว์เซอร์ .MPP เป็นรูปแบบไบนารีเฉพาะของ Microsoft Project ซึ่งเป็นเหตุผลที่โฟลเดอร์เต็มไปด้วยไฟล์เหล่านี้อาจให้ความรู้สึกเหมือนกล่องที่ล็อกไว้ เมื่อทั้งบริการและสิทธิ์ใช้งานหายไปแล้ว Ingantt แกะรูปแบบไบนารีนั้นได้โดยตรง และประกอบแต่ละโครงการกลับขึ้นมาเป็นแผนภูมิแกนต์แบบโต้ตอบที่สมบูรณ์ พร้อมงานย่อย ความสัมพันธ์ระหว่างงาน การกำหนดทรัพยากร หมุดหมายสำคัญ เส้นฐาน และเส้นทางวิกฤต ส่วน MS Project XML ก็เปิดได้ในแบบเดียวกัน

สำหรับหลายทีมก็ได้ และตรงนี้ควรพูดให้แม่นยำ Planner Premium นำเข้าไฟล์ .MPP ผ่านตัวช่วยสร้างใน Planner Power App และในระดับ Planner and Project Plan 3 รองรับเส้นทางวิกฤตและเส้นฐาน สิ่งที่มันทำไม่ได้ในทุกระดับคือการปรับสมดุลทรัพยากรและการจัดการมูลค่าที่ได้รับ ดังนั้นถ้าการติดตามของคุณตั้งอยู่บนแผนทรัพยากรที่ปรับสมดุลแล้วหรือบน EVM ส่วนนั้นจะไม่ตามไปด้วย ยังมีอีกสองเรื่องที่มักทำให้คนตกใจ การนำเข้า .MPP มีการสูญเสียข้อมูล โดยฟิลด์กำหนดเองจำกัดที่สิบฟิลด์ และคุณสมบัติของ Project ที่ไม่รองรับจะถูกตัดออกหรือปรับแก้ อีกทั้งเส้นทางวิกฤตและเส้นฐานเริ่มต้นที่ Plan 3 ซึ่งราคา 30 ดอลลาร์ต่อผู้ใช้ต่อเดือน ขณะที่ Plan 1 ราคา 10 ดอลลาร์ไม่รวมให้ นอกจากนี้มันยังสร้างบนฐานรากที่ต่างจาก Project Online ฟิลด์กำหนดเองระดับองค์กร มุมมอง PWA และรายงานที่ใช้ OData จึงย้ายไปตามเดิมไม่ได้

ไม่ใช่ และเรื่องนี้ควรพูดกันตรงๆ Project Online เป็นแพลตฟอร์ม PPM ระดับองค์กร ทั้งการวิเคราะห์พอร์ตโฟลิโอ เวิร์กโฟลว์เสนอโครงการและด่านอนุมัติตามระยะ แหล่งทรัพยากรระดับองค์กร ใบบันทึกเวลา และรายงาน OData Ingantt ไม่ได้ทำสิ่งเหล่านั้นเลย สิ่งที่ Ingantt แทนที่คือกลไกจัดตารางงานและตัวแผนเอง ได้แก่ เส้นทางวิกฤต ความสัมพันธ์ระหว่างงาน ปฏิทิน ทรัพยากร ต้นทุน เส้นฐาน และมูลค่าที่ได้รับ โดยทำงานในเบราว์เซอร์จากไฟล์ที่คุณส่งออกไว้แล้ว ถ้า PMO ของคุณต้องการชั้นพอร์ตโฟลิโอและการกำกับดูแล คุณต้องใช้ผลิตภัณฑ์ PPM แต่ถ้าสิ่งที่คุณต้องการคือให้ตารางงานหลายร้อยชุดยังใช้งานได้ตั้งแต่วันที่ 1 ตุลาคม นั่นคือโจทย์ที่แก้ได้ตรงนี้

ไม่ต้อง ปกติแล้วจุดติดขัดอยู่ตรงนี้พอดี บริการถูกยุติ สิทธิ์ใช้งาน Project มักหมดไปพร้อมกัน แต่ไฟล์ .MPP ยังอยู่ Ingantt ทำงานในเบราว์เซอร์ทั้งหมด ไม่ว่าจะเป็น Chrome, Safari, Firefox หรือ Edge บน Mac, Windows, Linux หรือ Chromebook โดยไม่ต้องติดตั้งลงเครื่องและไม่เกี่ยวกับสิทธิ์ใช้งาน Microsoft Project สำหรับคนที่แค่ต้องอ่านตารางงานที่เคยอยู่ใน PWA นี่คือการเตรียมการทั้งหมดที่ต้องทำ

แก้ไขได้ Ingantt เป็นเครื่องมือจัดตารางงานไม่ใช่โปรแกรมดูไฟล์ แผนที่ส่งออกไว้จึงวางแผนใหม่ได้ ขยับงานหนึ่งแล้วงานที่ขึ้นต่อกันและเส้นทางวิกฤตจะคำนวณใหม่ กำหนดและปรับสมดุลทรัพยากรได้ ตั้งและเปรียบเทียบเส้นฐานได้ พร้อมติดตามเปอร์เซ็นต์ความคืบหน้าและต้นทุนเทียบกับเส้นฐานนั้น เมื่อต้องส่งงานกลับไปให้คนที่ยังใช้ Microsoft Project ให้ส่งออกเป็น MS Project XML ซึ่ง Project เปิดได้โดยตรง

ได้ คุณจะได้ไฟล์แบบไหนขึ้นอยู่กับวิธีที่ใช้ส่งออก การเปิดแต่ละโครงการใน Microsoft Project บนเดสก์ท็อปแล้วบันทึกลงเครื่องจะได้ .MPP ส่วนสคริปต์ User Data Export แบบจำนวนมากของไมโครซอฟท์จะให้ข้อมูลแบบมีโครงสร้าง คือ CSV และ JSON แทนที่จะเป็นไฟล์โครงการ Ingantt นำเข้า CSV ได้ รายการงานที่ส่งออกด้วยวิธีนั้นจึงนำเข้ามาและประกอบกลับเป็นตารางงานได้ อย่างไรก็ตาม CSV พกมาเพียงแถวข้อมูล ไม่ใช่แบบจำลองการจัดตารางทั้งหมด ความสัมพันธ์ระหว่างงานและเส้นฐานที่ไม่เคยอยู่ในไฟล์ตั้งแต่แรกจึงกู้คืนจากมันไม่ได้ ตราบใดที่คุณยังเลือกได้ .MPP หรือ MS Project XML เก็บรักษาได้มากกว่ามาก

แผนโครงการก่อนเป็นอันดับแรก ในรูปแบบ .MPP หรือ MS Project XML เพราะรูปแบบเหล่านี้พกตารางงานมาได้ครบถ้วนที่สุด ทั้งงาน ความสัมพันธ์ระหว่างงาน การกำหนดทรัพยากร ปฏิทิน และเส้นฐาน ส่วนข้อมูลที่ไม่ได้อยู่ในแผนโครงการ เช่น ประวัติใบบันทึกเวลา นิยามฟิลด์กำหนดเองระดับองค์กร รายงานระดับพอร์ตโฟลิโอและข้ามโครงการ ต้องดึงออกมาต่างหากผ่าน OData API เป็น CSV หรือ JSON เพราะไฟล์โครงการไม่ได้บรรจุไว้ ถ้าคุณส่งออกเสร็จแล้ว ไฟล์ .MPP และ XML คือส่วนที่ Ingantt เปิดได้
