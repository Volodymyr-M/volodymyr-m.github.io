What carries out of Project Online, and what doesn't

An export is not one thing. The schedule travels inside the project file; most of what a PMO built around that schedule does not, and has to be pulled separately before the service closes.

A .MPP or MS Project XML file is a complete description of a schedule, and it is portable — that is why it is the format worth having. Open one and the plan is genuinely intact, down to the dependency lag and the task calendars.

What it was never designed to carry is the layer Project Online added around the schedule. Timesheet history, the enterprise resource pool, lookup tables, portfolio rollups, and the issues, risks, and documents that lived in each project's SharePoint site are all stored outside the project file, and they come out only through the OData API or the data export script, as CSV or JSON.

The practical consequence is that a folder of .MPP files is a complete backup of your plans and an incomplete backup of your PMO. Both are worth having, and only one of them opens in a scheduling tool.

Travels inside the .MPP or XML

  • Tasks, sub-tasks, and the outline structure
  • Dependencies and lag FS, SS, FF, SF
  • Durations, work, and start and finish dates
  • Constraints and deadlines
  • Project and task calendars
  • Resource assignments and rates as local resources
  • Baselines and the critical path
  • Percent complete, actuals, and costs
  • Milestones

Only through the OData or data export

  • Timesheet and actual-work history
  • Enterprise resource pool
  • Enterprise custom fields and lookup tables partly, as local fields
  • Portfolio and cross-project reporting
  • Issues, risks, and deliverables SharePoint lists
  • Project sites and documents
  • Workflow and stage-gate history
  • Security and permission model

The destinations Microsoft recommends, and what each one costs

There are three official paths off Project Online, and they are priced and scoped very differently. Which one fits depends on whether you are replacing a scheduling practice or an entire PMO platform.

Planner Premium is the path most Project Online customers are pointed at. It imports .MPP through the Planner Power App wizard, and on Planner and Project Plan 3 it does dependencies, critical path, and baselines. Two things are worth knowing before committing. The import is lossy — custom fields are capped at ten, and Project features it does not support are dropped or adjusted — and the scheduling features start at Plan 3 at $30 per user per month, where Plan 1 at $10 does not include them. Resource leveling and Earned Value are not available at any tier.

Project Server Subscription Edition is the closest thing to a like-for-like replacement, because it is essentially the same product running on your own infrastructure. It keeps enterprise custom fields, timesheets, portfolio management, and the PWA model largely intact. The cost is a server licence plus CALs plus somewhere to run it, and a rollout project measured in months rather than days — which is why it tends to suit organisations that already have SharePoint Server and the people to operate it.

Dynamics 365 Project Operations is the right answer for project-based businesses where the schedule is attached to quoting, contracts, billing, and revenue recognition. It is also by far the largest commitment of the three, at $135 per user per month for a full user licence, and it is an ERP-scale implementation, not a migration.

Ingantt is deliberately none of these. It replaces the scheduling half — the plans, the engine, and the tracking fields — for $5.99 per user per month, and it opens the files you already have without an implementation of any kind. If the portfolio and governance layer is what you actually need, one of the three above is the honest answer, and this page would rather tell you that than sell around it.

Microsoft has not committed to a read-only period or an archive mode after retirement, so anything not exported beforehand should be treated as gone rather than merely offline. The practical consequence is that the export you made is now the copy of record for those schedules, and it needs to open in something.
