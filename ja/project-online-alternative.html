サービス終了後に必要になるもの

エクスポートしたものを開けます

デスクトップ版 Project から保存したプロジェクトは .MPP になり、一括エクスポート用スクリプトはデータファイルを生成します。Ingantt は .MPP、MS Project XML、CSV をブラウザーで直接読み込みます。Microsoft Project のライセンスも、変換サービスも、Windows の仮想マシンも不要です。

本物のクリティカルパス スケジューリング

依存関係、制約、カレンダー、そして日付が動けば即座に再計算される生きたクリティカルパス。何年もかけて築いた計画は、平坦なカードの一覧ではなく計画のまま残ります。

ベースラインとアーンドバリュー

ベースライン、実績と計画の日付の対比、進捗率、コスト管理、アーンドバリュー。PMO のスケジュールが担う追跡項目であり、単なるタスク名ではありません。

テナント不要、移行プロジェクト不要

Google アカウントでサインインしてファイルを開くだけです。用意すべき環境も、立ち上げるサーバーも、誰かが再びスケジュールを読めるようになるまでの四半期がかりの切り替えもありません。

1 つのファイルを読むだけですか

.MPP を開いてスケジュールを読むだけなら、ブラウザーで 30 秒ほどです。.MPP ファイルの開き方をご覧ください。

Project Online から持ち出せるものと持ち出せないもの

エクスポートは一枚岩ではありません。スケジュールはプロジェクト ファイルの中を一緒に移動しますが、PMO がそのスケジュールの周囲に築いたものの大半はそうではなく、サービス終了前に別途取り出す必要があります。

.MPP や MS Project XML のファイルはスケジュールを余さず記述し、しかも持ち運べます。だからこそ手元に置く価値のある形式です。開けば計画は本当にそのまま、依存関係のラグやタスク カレンダーに至るまで残っています。

これらのファイルが決して担うようには作られていないのが、Project Online がスケジュールの周囲に足した層です。工数表の履歴、エンタープライズ リソース プール、参照テーブル、ポートフォリオの集計、そして各プロジェクトの SharePoint サイトにあった課題・リスク・ドキュメントは、いずれもプロジェクト ファイルの外に保管されており、OData API またはデータ エクスポート用スクリプトを通じて CSV か JSON としてのみ取り出せます。

実務上の結論はこうです。.MPP ファイルの入ったフォルダーは、計画の完全なバックアップであり、PMO の不完全なバックアップです。どちらも残す価値がありますが、スケジューリング ツールで開けるのは一方だけです。

.MPP や XML の中に含まれるもの

  • 制約と期限
  • プロジェクト カレンダーとタスク カレンダー
  • リソースの割り当てと単価 ローカル リソースとして
  • ベースラインとクリティカルパス
  • 進捗率、実績、コスト
  • マイルストーン

  • ポートフォリオおよびプロジェクト横断のレポート
  • 課題、リスク、成果物 SharePoint リスト
  • プロジェクト サイトとドキュメント
  • ワークフローとステージ ゲートの履歴
  • セキュリティと権限のモデル

マイクロソフトが推奨する移行先とそれぞれの費用

Project Online から離れる公式の道は 3 つあり、価格も対象範囲も大きく異なります。どれが合うかは、スケジューリングの実務を置き換えるのか、PMO プラットフォーム全体を置き換えるのかによって決まります。

Planner Premium は、多くの Project Online 利用者が案内される道です。Planner Power App のウィザードから .MPP を取り込み、Planner and Project Plan 3 では依存関係、クリティカルパス、ベースラインを扱えます。決める前に知っておきたい点が 2 つあります。取り込みは不可逆に情報が落ちること（カスタム フィールドは 10 個まで、サポートされない Project の機能は破棄または調整されます）、そしてスケジューリング機能は 1 ユーザー月額 30 ドルの Plan 3 から始まり、月額 10 ドルの Plan 1 には含まれないことです。リソースの平準化とアーンドバリューはどのプランでも利用できません。

Project Server Subscription Edition は、実質的に同じ製品を自社インフラ上で動かすものなので、最も同等に近い置き換えです。エンタープライズ カスタム フィールド、工数表、ポートフォリオ管理、PWA のモデルはおおむねそのまま維持されます。費用はサーバー ライセンスに CAL、そして稼働させる場所が加わり、導入プロジェクトは日数ではなく月数で測られます。すでに SharePoint Server と運用できる人員を持つ組織に向いているのはそのためです。

Dynamics 365 Project Operations は、スケジュールが見積り、契約、請求、収益認識と結びつくプロジェクト型ビジネスにとって正しい答えです。同時に 3 つの中で群を抜いて大きな投資でもあり、フル ユーザー ライセンスは 1 ユーザー月額 135 ドル、そしてこれは移行ではなく ERP 規模の導入です。

Ingantt は意図的にそのいずれでもありません。スケジューリングの側（計画そのもの、計算エンジン、追跡項目）を 1 ユーザー月額 5.99 ドルで置き換え、すでに手元にあるファイルを導入作業なしで開きます。本当に必要なのがポートフォリオとガバナンスの層であれば、正直な答えは上記 3 つのいずれかであり、このページはそれを脇に置いて売り込むより、そう申し上げることを選びます。

Project Online からの移行 — 実際によく聞かれること

マイクロソフトが定めた終了日は 2026 年 9 月 30 日です。それを過ぎると Project Online のサイトとその中のプロジェクト データにはアクセスできなくなります。PWA のインターフェイスは停止し、OData のレポート エンドポイントも応答しなくなります。終了後の読み取り専用期間やアーカイブ モードについてマイクロソフトは約束していないため、事前にエクスポートしていないものは単にオフラインになるのではなく失われたものとして扱うべきです。実務上、取得済みのエクスポートがそれらのスケジュールの正本であり、どこかで開ける必要があります。

Project Online のどちらの側が重要だったかによります。必要だったのがエンタープライズのポートフォリオ管理（提案ワークフロー、ステージ ゲート、エンタープライズ リソース プール、工数表、OData レポート）であれば、正直な答えは Project Server Subscription Edition か専用の PPM 製品であり、立ち上げには本格的なプロジェクトが必要です。日々実際に使っていたのがスケジュール（タスク、依存関係、クリティカルパス、ベースライン、リソース、コスト管理）であれば、エクスポート済みのファイルを読めるスケジューリング ツールなら移行プログラムなしで即座に作業を再開できます。Ingantt は後者です。

ブラウザーの Ingantt で開いてください。.MPP は Microsoft Project 独自のバイナリ形式であり、サービスもライセンスもなくなった後では、それらが詰まったフォルダーが鍵のかかった箱のように感じられるのはそのためです。Ingantt はこのバイナリを直接解析し、各プロジェクトをサブタスク、依存関係、リソース割り当て、マイルストーン、ベースライン、クリティカルパスとともに完全な対話型ガントチャートとして再現します。MS Project XML も同じように開けます。

多くのチームにとっては置き換えられます。ここは正確に述べる価値があります。Planner Premium は Planner Power App のウィザードから .MPP ファイルを取り込み、Planner and Project Plan 3 ではクリティカルパスとベースラインを扱えます。どのプランでもできないのはリソースの平準化とアーンドバリュー管理です。平準化されたリソース計画や EVM に基づいて管理している場合、その部分は引き継げません。ほかに 2 つ、見落とされがちな点があります。.MPP の取り込みでは情報が落ちること（カスタム フィールドは 10 個まで、サポートされない Project の機能は破棄または調整されます）、そしてクリティカルパスとベースラインは 1 ユーザー月額 30 ドルの Plan 3 から始まり、月額 10 ドルの Plan 1 には含まれないことです。さらに Project Online とは異なる基盤の上に構築されているため、エンタープライズ カスタム フィールド、PWA のビュー、OData を用いたレポートはそのままの形では移行できません。

いいえ。そこは率直に申し上げます。Project Online はエンタープライズ PPM プラットフォームでした。ポートフォリオ分析、提案およびステージ ゲートのワークフロー、エンタープライズ リソース プール、工数表、OData レポート。Ingantt はそのいずれも行いません。Ingantt が置き換えるのはスケジューリング エンジンと計画そのものです。クリティカルパス、依存関係、カレンダー、リソース、コスト、ベースライン、アーンドバリューを、すでにエクスポート済みのファイルを読み込んでブラウザーで扱えます。PMO にポートフォリオとガバナンスの層が必要なら PPM 製品が要ります。必要なのが数百本のスケジュールを 10 月 1 日以降も動かし続けることなら、まさにそれがここで解決する課題です。

不要です。多くの場合、ここが行き詰まりどころです。サービスは終了し、Project のライセンスも一緒になくなり、.MPP ファイルだけが残ります。Ingantt は Chrome、Safari、Firefox、Edge のいずれでも、Mac、Windows、Linux、Chromebook 上で完全にブラウザー内で動作し、ローカルへのインストールも Microsoft Project のライセンスも不要です。かつて PWA にあったスケジュールをただ読みたいだけの人にとっては、これが準備のすべてです。

編集できます。Ingantt はビューアーではなくスケジューリング ツールなので、エクスポートした計画は組み直せます。タスクを動かせば後続の作業とクリティカルパスが再計算され、リソースの割り当てと平準化、ベースラインの設定と比較、それに対する進捗率とコストの追跡が行えます。Microsoft Project を使い続けている相手に返す必要が生じたら、MS Project XML として書き出せば Project がそのまま開きます。

使えます。手元に残るファイルはエクスポートの実施方法によって変わります。各プロジェクトをデスクトップ版 Microsoft Project で開いてローカルに保存すると .MPP になり、マイクロソフトの一括スクリプト User Data Export はプロジェクト ファイルではなく CSV や JSON といった構造化データを出力します。Ingantt は CSV を取り込めるため、その方法でエクスポートしたタスク一覧を読み込んでスケジュールとして組み直せます。ただし CSV が持つのは行であってスケジューリング モデル全体ではないため、もともとファイルに含まれていなかった依存関係やベースラインを復元することはできません。まだ選べる状況であれば、.MPP か MS Project XML のほうがはるかに多くを保持します。

まずプロジェクト計画を .MPP または MS Project XML で。これらの形式がスケジュールを最も完全に保持します。タスク、依存関係、リソース割り当て、カレンダー、ベースラインまで含まれます。プロジェクト計画の中に存在しないデータ（工数表の履歴、エンタープライズ カスタム フィールドの定義、ポートフォリオ単位やプロジェクト横断のレポート）は、プロジェクト ファイルが担わないため、OData API から CSV か JSON として別途取り出す必要があります。すでにエクスポートが済んでいるなら、Ingantt が開くのは .MPP と XML のファイルです。
