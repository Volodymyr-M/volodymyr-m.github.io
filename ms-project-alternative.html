What carries across from Microsoft Project, and what does not

The schedule travels almost completely. Two things do not, and knowing which two before you switch is the difference between a good migration and a support ticket.

Open a .MPP or MS Project XML file in Ingantt and the plan is genuinely the plan. The outline structure, the dependency types and their lag, the constraints and deadlines, the project and task calendars, the resource assignments and rates, the baselines, the actuals, the costs, and the critical path all come through. A schedule that took months to build behaves the same way afterwards — move a date and the dependent work and the critical path recalculate.

The first thing that does not carry is the .MPP write path. Ingantt exports MS Project XML, which Microsoft Project opens directly, but it does not write the .MPP binary. In practice that means round-tripping with a colleague who still runs Project works — they open your .xml the way they open any project file — but you hand them XML, not .MPP.

The second is the enterprise layer. If your Project schedules sit inside Project Server, Project Online, or Planner Premium, then timesheets, the enterprise resource pool, enterprise custom fields and lookup tables, portfolio rollups, and stage-gate workflow live outside the project file. Ingantt replaces the scheduling half and says so; it does not replace a PMO platform. If that layer is what you actually need, a PPM product is the honest answer.
