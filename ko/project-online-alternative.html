Project Online에서 빠져나오는 것과 그렇지 않은 것

내보내기는 하나의 덩어리가 아닙니다. 일정은 프로젝트 파일 안에 담겨 이동하지만, PMO가 그 일정 주변에 쌓아 올린 것들은 대부분 그렇지 않아 서비스가 닫히기 전에 따로 꺼내야 합니다.

.MPP 또는 MS Project XML 파일은 일정을 빠짐없이 기술하며 이식성이 좋습니다. 그래서 확보해 둘 가치가 있는 형식입니다. 열어 보면 계획은 종속성의 지연 시간과 작업 달력까지 실제로 온전합니다.

이 파일이 애초에 담도록 설계되지 않은 것은 Project Online이 일정 주위에 덧붙인 계층입니다. 작업 시간표 이력, 엔터프라이즈 리소스 풀, 조회 테이블, 포트폴리오 집계, 그리고 각 프로젝트의 SharePoint 사이트에 있던 문제, 위험, 문서는 모두 프로젝트 파일 밖에 저장되어 있으며 OData API나 데이터 내보내기 스크립트를 통해 CSV 또는 JSON으로만 빠져나옵니다.

실무적인 결론은 이렇습니다. .MPP 파일이 담긴 폴더는 계획의 완전한 백업이자 PMO의 불완전한 백업입니다. 둘 다 확보할 가치가 있지만 일정 관리 도구에서 열리는 것은 한쪽뿐입니다.

Microsoft가 권장하는 이전 대상과 각각의 비용

Project Online에서 벗어나는 공식 경로는 세 가지이며 가격과 적용 범위가 크게 다릅니다. 어느 쪽이 맞는지는 일정 관리 업무를 대체하는지, PMO 플랫폼 전체를 대체하는지에 달려 있습니다.

Planner Premium은 대다수 Project Online 고객이 안내받는 경로입니다. Planner Power App 마법사로 .MPP를 가져오고, Planner and Project Plan 3에서는 종속성, 주 공정, 기준선을 다룹니다. 결정하기 전에 알아 둘 점이 두 가지 있습니다. 가져오기 과정에서 정보가 일부 손실되며(사용자 지정 필드는 열 개로 제한되고 지원되지 않는 Project 기능은 제외되거나 조정됩니다), 일정 관리 기능은 사용자당 월 30달러인 Plan 3부터 제공되어 월 10달러의 Plan 1에는 포함되지 않습니다. 리소스 평준화와 획득 가치는 어떤 요금제에서도 제공되지 않습니다.

Project Server Subscription Edition은 사실상 같은 제품을 자체 인프라에서 운영하는 것이므로 가장 동등한 대체에 가깝습니다. 엔터프라이즈 사용자 지정 필드, 작업 시간표, 포트폴리오 관리, PWA 모델이 대체로 그대로 유지됩니다. 비용은 서버 라이선스에 CAL, 그리고 운영할 환경이 더해지고, 도입 프로젝트는 일이 아니라 달 단위로 측정됩니다. 이미 SharePoint Server와 이를 운영할 인력을 갖춘 조직에 적합한 이유입니다.

Dynamics 365 Project Operations는 일정이 견적, 계약, 청구, 수익 인식과 연결되는 프로젝트 기반 비즈니스에 맞는 답입니다. 동시에 셋 중 압도적으로 큰 투자이기도 해서, 전체 사용자 라이선스가 사용자당 월 135달러이며, 이는 마이그레이션이 아니라 ERP 규모의 구축 사업입니다.

Ingantt는 의도적으로 그중 어느 것도 아닙니다. 일정 관리 쪽, 즉 계획 자체와 계산 엔진, 추적 항목을 사용자당 월 5.99달러에 대체하며, 이미 가지고 계신 파일을 어떤 구축 작업도 없이 엽니다. 정말 필요한 것이 포트폴리오와 거버넌스 계층이라면 정직한 답은 위의 세 가지 중 하나이고, 이 페이지는 그 옆에서 무언가를 파는 대신 그 사실을 말씀드리는 쪽을 택합니다.

Project Online에서 옮겨 가기 — 실제로 많이 받는 질문

Microsoft가 정한 종료일은 2026년 9월 30일입니다. 그 이후에는 Project Online 사이트와 그 안의 프로젝트 데이터에 더 이상 접근할 수 없습니다. PWA 인터페이스가 중단되고 OData 보고 엔드포인트도 응답하지 않습니다. Microsoft는 종료 후 읽기 전용 기간이나 보관 모드를 약속하지 않았으므로, 미리 내보내지 않은 데이터는 단순히 오프라인이 아니라 사라진 것으로 보아야 합니다. 실질적으로 받아 둔 내보내기 파일이 이제 그 일정들의 원본 사본이며, 어딘가에서 열려야 합니다.

Project Online의 어느 쪽이 중요했는지에 따라 다릅니다. 필요했던 것이 엔터프라이즈 포트폴리오 관리, 즉 제안 워크플로, 단계 승인, 엔터프라이즈 리소스 풀, 작업 시간표, OData 보고였다면 정직한 답은 Project Server Subscription Edition이나 전용 PPM 제품이며, 이를 갖추는 일은 그 자체로 하나의 프로젝트입니다. 매일 실제로 쓰던 것이 일정, 즉 작업, 종속성, 주 공정, 기준선, 리소스, 원가 추적이었다면 내보낸 파일을 읽는 일정 관리 도구가 마이그레이션 프로그램 없이 즉시 업무를 재개하게 해 줍니다. Ingantt는 후자입니다.

브라우저에서 Ingantt로 여세요. .MPP는 Microsoft Project의 독자적인 이진 형식이며, 서비스와 라이선스가 사라진 뒤 그런 파일로 가득한 폴더가 잠긴 상자처럼 느껴지는 이유가 바로 그것입니다. Ingantt는 이 이진 형식을 직접 해석해 각 프로젝트를 하위 작업, 종속성, 리소스 할당, 마일스톤, 기준선, 주 공정과 함께 완전한 대화형 간트 차트로 재구성합니다. MS Project XML도 같은 방식으로 열립니다.

많은 팀에게는 가능합니다. 여기서는 정확하게 짚는 것이 좋겠습니다. Planner Premium은 Planner Power App 마법사로 .MPP 파일을 가져오며, Planner and Project Plan 3에서는 주 공정과 기준선을 다룹니다. 어떤 요금제에서도 제공되지 않는 것은 리소스 평준화와 획득 가치 관리입니다. 평준화된 리소스 계획이나 EVM을 기반으로 관리해 왔다면 그 부분은 따라오지 않습니다. 또 두 가지가 흔히 예상을 벗어납니다. .MPP 가져오기에서 정보가 일부 손실되고(사용자 지정 필드는 열 개로 제한되며 지원되지 않는 Project 기능은 제외되거나 조정됩니다), 주 공정과 기준선은 사용자당 월 30달러인 Plan 3부터 제공되어 월 10달러의 Plan 1에는 포함되지 않습니다. 또한 Project Online과는 다른 기반 위에 만들어져 엔터프라이즈 사용자 지정 필드, PWA 보기, OData 기반 보고서는 그대로 옮겨지지 않습니다.

아닙니다. 이 점은 분명히 말씀드리는 것이 옳습니다. Project Online은 엔터프라이즈 PPM 플랫폼이었습니다. 포트폴리오 분석, 제안 및 단계 승인 워크플로, 엔터프라이즈 리소스 풀, 작업 시간표, OData 보고까지. Ingantt는 그중 어느 것도 하지 않습니다. Ingantt가 대체하는 것은 일정 계산 엔진과 계획 그 자체입니다. 주 공정, 종속성, 달력, 리소스, 원가, 기준선, 획득 가치를 이미 내보낸 파일을 읽어 브라우저에서 다룹니다. PMO에 포트폴리오와 거버넌스 계층이 필요하다면 PPM 제품이 필요합니다. 하지만 필요한 것이 수백 개의 일정을 10월 1일 이후에도 계속 돌아가게 하는 것이라면, 그것이 바로 여기서 해결하는 문제입니다.

필요 없습니다. 보통 여기서 막힙니다. 서비스는 종료되고 Project 라이선스도 대개 함께 사라지는데 .MPP 파일만 남기 때문입니다. Ingantt는 Chrome, Safari, Firefox, Edge에서 Mac, Windows, Linux, Chromebook 어디서든 전적으로 브라우저에서 동작하며, 로컬 설치도 Microsoft Project 라이선스도 필요하지 않습니다. 예전에 PWA에 있던 일정을 그저 확인해야 하는 사람에게는 이것이 준비의 전부입니다.

편집할 수 있습니다. Ingantt는 뷰어가 아니라 일정 관리 도구이므로 내보낸 계획을 다시 세울 수 있습니다. 작업을 옮기면 후속 작업과 주 공정이 다시 계산되고, 리소스를 할당하고 평준화하며, 기준선을 설정해 비교하고, 그에 대비한 완료율과 원가를 추적할 수 있습니다. 여전히 Microsoft Project를 쓰는 분에게 되돌려 보내야 한다면 MS Project XML로 내보내면 Project가 바로 엽니다.

쓸 수 있습니다. 어떤 파일이 남았는지는 내보내기를 어떻게 진행했는지에 달려 있습니다. 각 프로젝트를 데스크톱 Microsoft Project에서 열어 로컬에 저장하면 .MPP가 되고, Microsoft의 일괄 스크립트인 User Data Export는 프로젝트 파일 대신 CSV와 JSON 같은 구조화된 데이터를 만듭니다. Ingantt는 CSV를 가져올 수 있으므로 그렇게 내보낸 작업 목록을 불러와 일정으로 다시 구성할 수 있습니다. 다만 CSV는 행을 담을 뿐 전체 일정 모델을 담지 않으므로, 애초에 파일에 없던 종속성과 기준선은 거기서 복원할 수 없습니다. 아직 선택할 수 있다면 .MPP나 MS Project XML이 훨씬 많은 정보를 보존합니다.

먼저 프로젝트 계획을 .MPP 또는 MS Project XML로 내보내야 합니다. 이 형식들이 일정을 가장 온전히 담기 때문입니다. 작업, 종속성, 리소스 할당, 달력, 기준선까지 포함됩니다. 프로젝트 계획 안에 들어 있지 않은 데이터, 즉 작업 시간표 이력, 엔터프라이즈 사용자 지정 필드 정의, 포트폴리오 단위 및 프로젝트 간 보고는 프로젝트 파일이 담지 않으므로 OData API를 통해 CSV나 JSON으로 따로 받아야 합니다. 이미 내보내기를 마치셨다면 Ingantt가 여는 것은 .MPP와 XML 파일입니다.
